# Ideas not built (yet)

Bigger "nice to have" ideas, one-line pitch each. Not commitments.

- **Pre-commit hook:** run the fast half of the gate (lint, format, types) before each commit.
- **Import-boundary linter:** use `import-linter` contracts to enforce "checker never imports scheduler" in config as well as in a test.
- **Row-level security:** add Postgres RLS policies for customer scoping as a third layer behind `can()` and scoped queries.
- **Audit sign-ins:** record demo logins and sign-outs in the audit log (today only data writes are audited).
- **Expire idempotency keys:** a scheduled job that deletes keys older than, say, 24 hours (keys are not part of the audit trail).
- **Quote emails:** send `questions_for_customer` to the customer from the review page (needs an outbound-mail decision).
- **Price diff on approval:** if the price version changed since the last save, show old and new totals before approving.
- **Batch eval runs:** use the Message Batches API for `make eval --fresh` at half the cost.
- **Fix the colour rule mismatch for single-entry materials (quote prompt v2):** the prompt says "material and colour", the labelling rule says TPU and aluminium need no colour, so the model leaves them empty (q43, h04, h09, h28). Tune the prompt on the **dev split only**, and keep the pre-fix held-out score in `eval/results/RESULTS.md` as the honest number next to the new one.
- **Dates as raw text, resolved by code:** have the model return the deadline exactly as written ("12 januari", "le 20/11") and let code parse it, with month names in every supported language, so a misread like "12 januari" becoming December (h19) cannot happen.
- **Exact changeovers that actually help:** revisit AddCircuit (D49) with longer limits, several workers for a non-repeatable "best effort" mode, or a large-neighbourhood search that re-sequences one machine at a time.
- **Split large jobs** across printers when one machine would make them late.
- **Slicer-based print times** instead of the minutes-per-part formula.
- **Disruptions as raw checker input (M6):** pass machine-down and staff-off events into the plan document so the checker applies them itself, instead of trusting changed shifts or staff (today a mismatch with the config is refused, D62).
- **Measure solver variance:** run each 80-job instance under several equivalent model orders or seeds and report the spread, since one CP-SAT run at 80 jobs is one sample (D67).
- **Near-miss mutations:** generated changes that must stay valid (a gap of exactly the changeover time, tasks that just touch), to measure false alarms the way mutations measure misses.
- **Carry finished manual work into a new plan:** give the scheduler "done" prep and post tasks as facts, so a re-plan does not ask for them again (today only machine work is fixed, README limits).
- **A separate planning worker process** reading the planning_runs table, for more than one engine (D68).
- **Operators report disruptions** from their queue ("jammed" next to the running task), for a planner to confirm.
- **A promised date per order**, set when the customer is told, as the re-planning reference instead of the approved plan's finish (D84).
- **Ask the operator for an estimate** when a print runs over, instead of the configured margin (D86).
- **Real free-licence test models (M7):** add a handful of CC0 or public-domain printable models (with their licence recorded) to the held-out file set, so the false pass rate is also measured on parts that are not simple shapes.
- **Overhangs in the best orientation:** try the six flat orientations and report the one with least support, instead of only the orientation the file was saved in.
- **Thin features on curved parts:** a voxel or distance-field wall check for parts where one ray per face is too coarse.
- **Live vision advice:** switch on `[advice]` with a vision model once a key is approved, and evaluate the advice blind like the other AI steps.
- **Re-check a file when its line changes:** when staff change a line's material, run the stored file's checks again for the new process instead of asking for a new upload (D111).
- **Saved searches:** name a filter and show its count on the home page ("overdue rush jobs: 2").
- **Explain an unclear question with code:** list which words the reading could not place in any field, instead of one general message.
- **A lint rule for accent links on grey backgrounds,** since the same contrast mistake happened twice (#55, #65).
- **Reprint only the failed parts:** when 3 of 10 parts fail, plan a reprint job for 3, not the whole line.
- **Correct a recorded time:** let a planner fix a Done pressed hours late, with the change audited, so actual times stay honest.
- **Flag by material and post-processing, or by machine,** once the shop has enough jobs that the smaller groups still reach the minimum sample.
- **Flag over-quoting too** (types that always finish well under their quote), where the shop may be losing work on price.
- **Stock counts:** a planner records a counted balance, logged as a correction with the difference, so the "count is due" warning can be cleared.
- **Material per part as it prints:** take grams over the print instead of all at the start, for long multi-part prints on one spool.
- **Expedite or move a delivery:** let staff change a purchase order's expected time (audited) instead of reporting it as a disruption.
- **Need times with capacity:** work back from due dates through the plan's own machine queues, so shortages are found earlier when machines are busy.
- **A faster gate self-test:** it runs the whole gate per planted mistake (about 4 minutes each, over 2 hours for 32); running only the gate steps up to the expected one, and only the test files a mutation touches, would cut it to minutes at the cost of proving less.
- **One real machine:** run an adapter against a real OctoPrint or Moonraker instance (or the vendors' own simulators) and record where the mock differed.
- **TLS for the Bambu mock,** with a self-signed certificate, so the adapter's TLS path is exercised as on a real printer.
- **Dispatch to another eligible machine** when the planned one is down, as a proposal the guard checks with a one-job re-plan through the checker.
- **Edit JavaScript only with exact edits:** twice a Python-written edit put a real line break inside a JavaScript string (#86, and once in M9, caught before commit by the parse step); a small script that rewrites JS through a JS parser would remove the trap.
- **A pin button on the icon rail,** so a person who prefers labels can keep it open (remembered per browser).
- **Drag to zoom the board timeline** between the three-day and whole-plan widths, with keyboard steps, instead of two fixed spans.
- **A design-shot comparison in CI:** keep the approved design shots and flag a screen whose pixels move more than a set amount.
