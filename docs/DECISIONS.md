# Decisions

Every decision, deviation from the brief, and addition. Newest at the bottom of each milestone. Keep entries short:
**what**, **why**, **alternative considered**.

## M0. Scaffold and quality gate (2026-10-25)

| # | Decision | Why | Alternative considered |
|---|---|---|---|
| D1 | Moved `BRIEF.md` and `MILESTONES.md` into `docs/`. | CLAUDE.md refers to `docs/BRIEF.md`; paths should match the instructions. | Leave them in the root and edit CLAUDE.md. |
| D2 | Added `config/` (dated config) to the suggested layout. | Hard rule 8 ("config, not memory") needs one obvious home for model names, prices, thresholds, weights. | Scatter config per service. |
| D3 | All task logic lives in one Node script, `scripts/tasks.mjs`. `make <x>` and `pnpm run <x>` are thin aliases of it. | Tested on this machine: from PowerShell, GNU make ran recipes with `cmd.exe` (and `bash` on PATH is WSL, not Git Bash); from Git Bash it used bash. Node is always installed and behaves the same everywhere. Verified `make gate` and `pnpm run gate` from both shells. | Shell recipes in the Makefile (flaky across shells); `just` (another tool to install). |
| D4 | Python tooling is **uv** with `uv.lock`, Python pinned to 3.12. | One command creates the venv with the right Python; lockfile makes installs reproducible. 3.12 is the safest version for OR-Tools (M3) and mypy. | pip + venv + requirements.txt; Python 3.14 (newer, wheel support less certain). |
| D5 | pnpm installed with `npm i -g pnpm`, not corepack. | `corepack enable` needs admin rights on Windows (EPERM writing to Program Files). | Run corepack as admin. |
| D6 | TypeScript pinned to 6.0.3, not 7.0. ESLint kept at 9, not 10. | `typescript-eslint` 8.72 (used by `eslint-config-next`) supports TypeScript `<6.1.0`. `create-next-app` 16.4.3 itself picks ESLint 9, and its React plugins are not confirmed on 10. | TypeScript 7 with no type-aware linting; ESLint 10. |
| D7 | PostgreSQL 18.6 (alpine) on host port 5433. | Current stable. 5433 avoids clashing with a locally installed Postgres. Volume mounts at `/var/lib/postgresql`, the Postgres 18 image layout. | Postgres 17. |
| D8 | Vitest for web unit tests, Playwright (Chromium only) for browser tests. | Vitest needs little config with TypeScript. Chromium only keeps setup and CI small. | Jest; all three Playwright browsers. |
| D9 | The gate does not touch the database in M0. | Nothing to test yet. `setup` starts Postgres and waits for its health check. DB tests join the gate in M1. | A ping test in M0 that proves little. |
| D10 | Added `gate-selftest`: refuses a dirty git tree, exports the last commit with `git archive` into `.selftest/` (git-ignored), requires a green baseline, then plants 9 errors one at a time (one per gate step except the build and database start; M1 added a route-rename mutation for the API-types check and a permission-widening mutation for engine tests) and requires the gate to fail **at the step meant to catch it**. Deletes the copy afterwards. | Turns "the gate fails on errors" into a command result, not a claim (hard rule 11). The copy means the real tree is never modified. The baseline stops a broken copy from making every mutation look "caught". | A manual demonstration; mutating the real tree and restoring with git (risky if interrupted). |
| D11 | Engine tests use `httpx2`, and pytest treats warnings as errors. | Starlette 1.10 deprecated plain `httpx` for its TestClient. Failing on warnings surfaces the next deprecation instead of hiding it. | Keep `httpx` and ignore the warning. |
| D12 | System fonts, no `next/font/google`. Template logos and the default favicon removed; replaced with an original SVG mark. | Fetching fonts at build time makes the gate depend on the network. Default assets are a real company's branding. | Self-hosted font files (decide with the visual direction in M5). |
| D13 | The gate runs `next build`, and Playwright tests that production build on port 3100. | Build errors fail the gate. A separate port means a running `pnpm dev` can never be tested by mistake. | Test against `next dev` (faster, but skips the build). |
| D14 | `turbopack.root` and `outputFileTracingRoot` set to the repo root in `next.config.ts`. | Next guesses the workspace root from lockfiles in parent folders; the self-test copy sits inside the repo and could be mistaken for it. | Put the copy in the OS temp folder. |
| D15 | Compose uses a fixed project `name: brimline`, not a fixed `container_name`. | Every checkout shares one DB container instead of failing on a name clash (see DEFECT_LOG #1). | Per-checkout databases (more ports to manage). |
| D16 | `typecheck` runs `next typegen` before `tsc`. Next telemetry is disabled in the task runner. | Route types such as `LayoutProps` exist only after typegen, so a fresh clone failed `tsc` without it. A quality gate should not send telemetry. | Commit generated types. |

## M1. Base app, database, demo roles (2026-10-25)

| # | Decision | Why | Alternative considered |
|---|---|---|---|
| D17 | The engine owns all database access; the web app only calls the engine over HTTP. | One place enforces permissions, idempotency and audit (hard rules 4 and 6), and one definition of the tables. | Next.js doing CRUD through its own ORM (faster screens, two data layers). |
| D18 | Plain SQL migrations in `db/migrations/`, applied by a ~100-line runner that stores a checksum per file and refuses an edited one. | Triggers and grants are SQL anyway; the files read top to bottom. | Alembic; yoyo-migrations. |
| D19 | psycopg 3 with hand-written parameterised SQL, no ORM. Rows map to pydantic models with `class_row`. | Every query is visible (hard rule 5); fewer concepts. | SQLAlchemy. |
| D20 | Two database roles. The owner (`POSTGRES_USER`) runs migrations and the seed. The engine connects as `brimline_app`, which has explicit per-table grants only, no `DELETE` on orders, and `SELECT`/`INSERT` only on `audit_log`. The runner refuses a `DATABASE_URL` that is not `brimline_app`. | Defence in depth for the append-only log: the trigger stops mistakes; missing privileges stop a compromised app from changing rows, disabling the trigger, or changing the schema. In this local setup the owner is the container's superuser; a deployment should use a non-superuser owner (M11). | Trigger only. |
| D21 | Session token: `v1.<payload>.<HMAC-SHA256>`, stdlib only, with expiry and `hmac.compare_digest`. Stored in an httpOnly, SameSite=Lax cookie (Secure in production). Demo routes exist only when `DEMO_LOGIN=true`; the default is off. The `.env.example` placeholder secret is refused. | Small enough to explain line by line. Off-by-default means a deployment cannot ship demo login by accident. | PyJWT or itsdangerous; a full auth library (more than a demo login needs). |
| D22 | Idempotency keys are scoped to (user, endpoint, key). The request inserts its key row first, inside the write's transaction, with `ON CONFLICT DO NOTHING`. A concurrent duplicate blocks on the primary key until the first commits, then replays the stored response. A failed write rolls back its claim, so the key can be retried. Same key with a different body is 409. | Exactly-once with no extra locking code; the database does the waiting. | Advisory locks; deduplicating on content. |
| D23 | Permissions are a pure, default-deny `can(actor, action, target)` plus `order_scope()`. The domain layer (`orders.py`) calls them itself, and order queries are also scoped in SQL. Another customer's order is a 404 with the same body as a missing one; unknown customer codes are 403 for customers and 422 only for roles that may list customers. | Routes cannot forget a check; nothing reveals that someone else's order exists. | Row-level security in Postgres (kept as an idea). |
| D24 | Tables are named `machines` (not `printers`), because the shop also has a CNC mill. Orders have one job per line; tasks are a table only, generated by the scheduler in M3. Price rules live in `config/shop.toml` now and become the dated `price_rules` table in M2. | Keeps M1 to its acceptance criteria. | Creating the price tables now. |
| D25 | Seed config is TOML (stdlib `tomllib`), validated by pydantic including cross-references, with a fixed `seed_time` so two seeds are identical. The seed writes no audit rows (it is setup, not an app write). | No extra dependency; a typo fails before any SQL runs. | YAML; Faker. |
| D26 | Web types are generated from the engine's OpenAPI schema (`openapi-typescript`), used with `openapi-fetch`; the gate fails if the committed file is stale. zod validates form input in the web for friendly messages; the engine re-validates and is the authority. | Web and engine cannot drift silently. | Hand-written types. |
| D27 | Next 16 Cache Components stays on. Every session read sits inside `<Suspense>`, request-time fetches call `connection()` first, and nothing session-derived is cached. | Follows the bundled "authentication with Cache Components" guide; no caching means permissions shown are always current. | Turning Cache Components off. |
| D28 | Test isolation: engine tests rebuild `brimline_test`, browser tests reset `brimline_e2e` and run the engine on port 8100 and web on 3100. The engine's clock is a dependency (`utc_now`), fixed in API tests. | Dev data is never touched; date rules are deterministic. | One shared database. |
| D29 | Added dependencies: psycopg, psycopg-pool, pydantic-settings, tzdata (Windows has no system time-zone data); zod, openapi-fetch, openapi-typescript (dev), server-only. | Each is small and has one job; `server-only` makes the build fail if token-handling code reaches the browser. | Doing without (more hand-written code). |
| D30 | ruff `E501` off (the formatter owns line length; long lines left are SQL strings), and `ANN401` off in tests only. | Readable SQL; test clients are untyped. | Splitting SQL into fragments. |
